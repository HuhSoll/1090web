## 2. 実装した UX 改善

- **配置**：右のパネル（影響の分析）、下のシナリオタイムライン（時間とイベント）、地図の上の小さな操作パネル（表示モード、停止前の確認、凡例）。左のサイドバー（検索・絞り込み）はそのまま。
- **優先順位**：パネルの最上部は、条件の1行（方式・基準・期間・区分・有向）と意味の1文、重大な警告、そして影響の要約（4枚のカード）。詳細は折りたたみ（影響を受けた空港／経路と原因／詳細分析／条件／保存と出力／仮定と限界）。内容の高さは 2,499 px → 約 1,070 px（折りたたみを閉じた状態）。1366×768 でも要約は最初の画面に入ります。
- **要約カード**：失われた直接接続（前 → 後と変化量、単位付き）、影響対象の観測便数（構造・時刻照合で名前と意味が変わる）、経路がなくなった空港の組（波及）、最も影響を受けたほかの空港。カードを押すと、それぞれ「失われた接続だけを地図に表示」「内訳」「その空港の組の経路比較」「影響空港の地図表示とランキング」に移動します。
- **イベント編集**：地図で空港・路線を選んで「今から6時間停止」「期間中ずっと停止」。タイムラインの帯をドラッグして移動、端をドラッグして開始・終了（1時間単位、Alt で15分）。正確な時刻は編集欄に UTC で入力。名前、出典（仮想／報告済み）、出発・到着の別、有効・無効、複製、削除。元に戻す・やり直す（ボタンと Ctrl+Z／Ctrl+Shift+Z、ドラッグ1回が1手順）。
- **用語の統一**：観測ネットワーク（障害前）／仮想障害後のネットワーク（障害後）／直接の影響／波及（停止していない空港どうし）。

## 3. Scenario Timeline の仕様

- 時間軸の上に、イベントを1行ずつ帯で表示します（空港の停止は赤、路線の停止は黄、無効は斜線、開始・終了を限定しない側は破線、現在有効なものは濃く表示）。行のラベルは名前（なければ対象）と「出典」の印。
- 現在時刻のカーソル（クリック・ドラッグで移動）、前後のイベント境界へのジャンプ、1ステップ移動、再生・一時停止、速度（遅い・標準・速い）、移動幅（1時間・6時間・1日）、拡大・縮小・全体表示。
- 時計は1つです。シミュレーションの時刻は Temporal Explorer のカーソルそのもので、再生も同じ仕組みを使います。再生は各時刻のシミュレーション結果が出てから次へ進み、タイムラインの終わりで止まります。
- 帯の下に「影響の時間変化」の図（失われた接続、影響対象の観測便、経路のない組）。図を押すとその時刻に移動します。
- 固定の基準では基準期間を薄く、2026年5月5〜7日の収集欠損を斜線で表示します。

## 4. イベントの発生・終了・復旧の計算方法

- 期間は UTC の半開区間 [開始, 終了)。12:00〜18:00 の停止は 18:00 ちょうどには停止していません。
- **構造**：シミュレーション時刻に有効なイベントの集合で、ネットワークの状態が決まります（固定・時間窓連動のどちらでも）。9C の「時間窓と重なるイベントは窓全体に適用」という扱いは使いません。停止が終わると、その空港・路線は基準ネットワークの状態に戻ります（仮想的な制限の解除で、運航が同じ速さで戻る予測ではありません）。
- **段階的な復旧**：空港・路線ごとに違う終了時刻を指定すれば、そのまま再現されます（テスト：JFK 12:00〜翌6:00、HND 18:00〜翌々日12:00 → 0, 3, 4, 2, 0 接続）。
- **容量の部分的な削減**：観測データから運航可能な便数を正しく解釈する根拠がないため、実装していません（完全停止と解除の組み合わせのみ）。
- **重複**：イベントの集合から区間の和集合を作るため、同じ便・路線を二重に数えません（3つの重なるイベントで 125 接続・369 便＝単独停止と同じ）。

## 5. 地図の表示

| モード | 内容 |
| --- | --- |
| 変化のみ（既定） | 失われた接続（オレンジの破線）と便数が減った接続（オレンジ）だけ。変化のない接続は描かない。停止した空港は赤い点 |
| 前後を重ねる | 9C の表示。変化のない接続は薄い灰色 |
| 障害後 | 仮想障害後のネットワーク |
| 影響空港 | 停止していない空港を、ランキングで選んだ指標（到達できなくなった空港／2ホップ以内の減少／直接接続の減少）の大きさで表示 |
| 停止前を見る | 押している間（または B キーを押している間）観測ネットワーク。短く押すと固定、もう一度で戻る |

カメラの位置・ズームはモードを変えても変わりません。ランキングの行や要約カードから空港を選ぶと、地図・地球儀がその空港に移動します。経路の比較では、その経路を地図に太線で表示します。レンダラーへの追加は、9C で入れた「停止空港」の状態に、影響空港を既存の「接続」スタイルで示す指定だけです。

## 6. 直接の影響と波及効果の表示

要約カードで「失われた直接接続」「影響対象の観測便数」（直接の影響）と「経路がなくなった空港の組」（波及）を分けて表示し、ネットワーク効率はシステム全体と波及を1行で並べます。詳細分析に全体・波及の表（到達可能、1〜3ホップ、効率、連結成分）と、イベントを1つずつ除いた比較を置きました。

**原因をたどる**：空港の組を選ぶと、障害前の最短経路、障害後の経路の有無、元の経路に含まれていた停止空港、障害後につながっていない区間を表示します。「イベントごとに確認」では、各イベントを1つ除いた場合の最短ホップ数を計算します（構造のみ）。複数のイベントが重なるとき、1つのイベントを原因と断定しません。イベント別の差は合計しても全体と一致しないことを表示します。

## 7. Fixed / Dynamic の時系列処理

- **固定**：基準ネットワークは変わらず、時刻によって変わるのは有効なイベントだけです。結果は「有効なイベントの集合」をキーに保存し、同じ集合の時刻は同じ結果を使います。時系列は各ステップとすべてのイベント境界で計算するため、階段状のグラフは境界の間で正確です。
- **時間窓に連動**：各時刻で、その時刻の観測の時間窓（1日・直近24/6/1時間）と、同じ時間窓の障害後を必ず対にして計算します。時系列は再生で計算した時刻から順に埋まり、「全時点を計算」でまとめて計算できます。
- **時刻照合**：固定の基準では、基準期間の記録を照合した結果は時刻によって変わらず、時系列は時間ごとの影響対象の便数です。時間窓に連動では、時間窓ごとに記録を照合します。イベント集合が同じでも時間窓が違えば対象の便が変わるため、結果を使い回しません（キーに時間窓が入る）。
- 補間はしません。計算していない時刻は空欄です。

## 8. Research Mode との統合

「{時刻} の状態を Research Mode で分析」で、基準期間、シミュレーション時刻（構造）、有効なイベント、方式、条件をそのまま渡し、比較タブで観測ネットワークと比べます。比較の選択肢に「{イベント} を除いた同じシナリオ」を追加し、イベントを無効にした場合を同じ分析方式で比べられます。

## 9. 保存・再現性

- シナリオの形式をバージョン 2 にしました（イベントの名前、タイムラインの範囲とステップ、計算方法のバージョン `9d.1`）。保存するとシミュレーション時刻も記録されます。
- バージョン 1（9C）のファイルは読み込めます。時刻付きのイベントがあり評価時刻のない固定・構造のシナリオは、9C では期間と重なるイベントをすべて適用していたため、期間内で最も早いイベントの開始を評価時刻にして、そのことを表示します。期間中ずっとのイベントだけのシナリオは結果が変わりません。9C の URL も同じ扱いです。
- 出力の追加：イベント一覧（CSV）、時系列（CSV：時刻、有効なイベント、失われた接続、影響対象の便、経路のない組、効率、計算方法）。結果の JSON には時系列、シミュレーション時刻、計算方法のバージョンを入れました。

## 13. 残っている UX 上の問題

- 左のサイドバー（検索・絞り込み）が常に表示されるため、1366×768 では地図の幅が約 700 px です。シミュレーション中に折りたためると広くなります。
- タイムラインのイベントが多い（5 件以上）と行がスクロールになります。行の高さの調整やグループ化はしていません。
- 時間窓に連動の時系列は、全時点を計算するまで空欄があります（計算の負荷を抑えるため）。
- ドラッグの単位は 1 時間（Alt で 15 分）で、分単位は編集欄で入力します。
- 影響空港の地図表示は、選んだ指標の大きさを点の大きさで表すだけで、凡例に値の範囲を出していません。

## 14. Phase 9E への引き継ぎ

- イベントの評価：`eventActiveAt`、`activeSignature`、`boundaries`（`disruption.ts`）、時系列：`series.ts`。新しい種類のイベントもこの関数群に乗せれば、タイムライン・時系列・保存がそのまま使えます。
- 実際の出来事（安全勧告など）をタイムラインに重ねる場合、`SAFETY_ADVISORY` は表示だけで、ネットワークからは何も除きません。報告済みのイベントには出典（`sourceReference`）が必要です。
- 容量の部分的な削減を入れる場合は、観測データからの解釈の根拠を先に決め、停止の和集合の後に、methodology に書いた順序で適用します。
- 時間窓に連動の時系列は 1 点 0.2〜0.3 秒です。長い期間の事前計算を入れるなら、Web Worker での並列化と、時間窓の集計結果のキャッシュの拡張が候補です。
