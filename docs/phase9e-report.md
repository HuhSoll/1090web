## 2. Systemic と Spillover の定義

候補の空港 v を1つだけ止め、その前後でネットワーク効率（順序付きの組の 1/d の平均、重みなし・有向が既定）がどれだけ下がるかを測ります。

- **Systemic**：空港の集合は固定で、止めた空港は孤立ノードとして残す。n(n−1) 組。v 自身の組も含む。
- **Spillover**：空港の集合は V \ {v}。「前」は v を通る経路も含めた距離、「後」は v を通れない距離。(n−1)(n−2) 組。

主な指標は Spillover の効率の低下です。あわせて、到達できなくなる組、1・2・3 ホップ以内の組の割合の低下、失われる直接接続、v の路線の便数も記録します。定義は Phase 9C のシミュレーションと同じで、空港を1つ止めたシナリオと全候補で一致することをテストしています。

## 3. Sensitivity Analysis

ネットワークを作り直す条件を変え、同じ候補の順位を比べます。

- ティア：T1〜T4 / T1〜T3 / T1 のみ
- 便数の閾値：1 / 4 / 10
- 有向／無向、機材の区分（旅客のみ）、時刻の基準（航跡開始のみ）、期間（3月前半）、地域

条件ごとに空港の集合は変わります。候補のリストは基準のネットワークで固定し、ある条件に存在しない空港は影響 0 として扱い、`absent` に数えます。順位の比較は、固定した候補リストの上と、両方に存在する空港だけの上（「共通」）の両方で計算します。

T1 のみの条件は「より正確」なネットワークではなく、受信網の薄い地域の便を落とした条件として扱います（12 節）。

## 4. Missingness Simulation

観測された便を、想定したモデルで便ごとに取り除き、残った便から路線を数え直して閾値を適用し、ネットワークを作り直します。便を加えることはしません。

- 空港の集合は基準のネットワークに固定します。すべての接続を失った空港も孤立ノードとして残すので、効率の分母は試行間で変わりません。
- 1つの試行の中では、全候補が同じ欠けたネットワークで評価されます。
- 試行 0 は欠測なし（基準）。統計は試行 1〜R だけで計算します。

## 5. 欠測モデルの詳細

| モデル | 便が落ちる確率 | 3月の実験で使った値 |
| --- | --- | --- |
| A 一様 | すべての便で p | p = 10% |
| B 地域別 | 出発地・到着地の大陸の確率を組み合わせる | アフリカ 30%、南米 20%、アジア 15%、オセアニア 15%、それ以外 5%。組み合わせは高いほう（max） |
| C 低頻度路線 | 基準ネットワークで組の便数が閾値未満なら rateLow、それ以外は rateOther | 閾値 4 便（3月・T1〜T4・両方向）、rateLow 30%、rateOther 0%、単位は便ごと |

B の組み合わせ規則は max（既定）、either = 1 − (1 − po)(1 − pd)、both = po · pd、origin、destination から選べます。C は、各便が独立に欠ける「便ごと」と、低頻度の路線が丸ごと消える「路線ごと」を区別し、判定に使った閾値と期間を定義に記録します。

B の地域別の確率は、大陸別の T1（航跡で確認できた便）の割合が低い地域ほど高くなるように置いた**仮定**で、実際の欠測率の推定値ではありません。

## 6. 乱数・再現性

- 試行 t の乱数は（シード, t, ストリーム）だけから作ります。Python は `SeedSequence([seed, t, stream])` と PCG64、ブラウザは同じ3つの値から作ったシードの mulberry32 です。どの順で、何並列で実行しても同じ結果になります。
- Python は便を flightId の順に並べてから乱数を割り当てます。ブラウザは集計済みの行の便1本ずつに乱数を引きます（モデルは同じで、乱数列は異なる）。
- 経路計算の起点のサンプルは `sourceSeed` から作り、両言語で同じ空港になることをテストしています。
- 定義のハッシュ（名前と ID を除く）を結果に記録します。ハッシュ関数は言語ごとに異なります。
- ブラウザで同じ定義を2回実行し、表示されるすべての数値が一致することを確認しました（17 節）。

## 7. Python Batch Research

```bash
cd pipeline
../.venv/Scripts/python -m experiments.run <定義.json> --out ../data/experiments/<名前> --workers 11 [--resume]
```

- 候補を 48 件ずつに分けて `multiprocessing`（spawn）で並列に計算し、終わった分を `chunks/` に保存します。止まっても `--resume` でその続きから再開します。
- 実行ごとの記録（`runs/`）、統計と比較をまとめた `result.json`（研究モードで読み込める形式）、`rankings.csv` を書き出します。
- 失敗した分はエラーとして記録し、結果を `complete: false` にします。
- 研究モードの「バッチ用の定義」で、ブラウザで組んだ実験をそのままバッチの定義として保存できます。

## 8. 計算の高速化

- 経路は scipy の C 実装の幅優先探索（`shortest_path`、重みなし）で計算し、256 起点ずつまとめて行列で集計します。
- Spillover の「前」は、候補ごとに探索し直さず、最初の1回の探索の行和・列和から v の行と列を引いて求めます。候補1件あたりの探索は「後」の1回だけです。
- 近似では、全候補で同じ起点のサンプルを使います。
- ブラウザは Web Worker で計算し、画面を止めません。実行前に経路探索の回数と、基準ネットワークで測った1回の時間から所要時間を見積もります。

## 9. 厳密計算と近似計算

3月の基準ネットワーク（有向、T1〜T4、閾値 1、3,883 空港・92,592 弧）で、全 3,883 空港を候補にして厳密計算と近似（起点のサンプル）を比べました。

| 計算 | 時間（11 並列） | Spillover：厳密との Spearman | 上位 10 / 20 / 50 / 100 の一致 | 上位 50 の相対誤差（中央値） |
| --- | --- | --- | --- | --- |
| 厳密（全起点） | 1,365 秒 | — | — | — |
| 256 起点（シード 1） | 100 秒 | 0.517 | 0.40 / 0.55 / 0.62 / 0.81 | 46% |
| 256 起点（シード 2） | 94 秒 | 0.566 | 0.50 / 0.45 / 0.64 / 0.81 | 45% |
| 256 起点（シード 3） | 96 秒 | 0.575 | 0.80 / 0.60 / 0.62 / 0.78 | 43% |
| 1,024 起点（シード 1） | 401 秒 | 0.675 | 0.80 / 0.80 / 0.80 / 0.85 | 19% |

- 256 起点では、シード 1 と 2 の上位 10 の一致は 4 空港、上位 20 は 10 空港でした。順位の誤差が、欠測によるばらつき（12 節）よりはるかに大きくなります。
- 誤差は起点の数の平方根にほぼ反比例して減ります（256 → 1,024 で 46% → 19%）。
- Spillover は、周辺の小さなネットワーク（西オーストラリアの鉱山空港群、アラスカの小空港など）から出る組がまとまって1つの空港に頼っているときに大きくなります。こうした組の起点がサンプルに何個入るかで推定値が大きく変わるため、ばらつきが大きくなります。
- Systemic の上位 50 の一致も 256 起点で 0.36〜0.44 でした。

この結果を受けて、次のようにしました。

- 実データの主な実験（12〜14 節）は、厳密計算に切り替えました。候補は、厳密な基準で Systemic または Spillover の上位 150 に入った空港の和集合（157 空港）に絞っています。全 3,883 空港を候補にした近似の実験は、比較のために残しています。
- ブラウザの既定を 1,024 起点にし、起点の選択肢を 256 / 1,024 / 2,048 / 厳密にしました。近似のときは、上の誤差を画面に表示します。

## 10. Python / TypeScript の照合

- 起点のサンプル：同じ (n, k, シード) で同じ空港を選ぶことをテスト（Python 側に TS の出力を固定値として記録）。
- 影響の計算：Python が書き出した 8 ケース（無作為なグラフ 2 種 × 有向・無向 × 厳密・12 起点）で、TS の全指標（9 種、全候補）が 1e-10 以内で一致。fixture は `tests/experiments/crosscheck.fixture.json`。
- 定義の確認：Python は素朴な幅優先探索で定義どおりに計算した値と、TS は Phase 9C の影響計算と、全候補で一致。
- 統計：順位（"1224"）、上位 k の重なり、分位点（numpy の線形補間）、標準偏差（ddof = 1）を同じ値で検証。
- 欠測の乱数列は言語ごとに異なるため、欠測の試行は分布としてだけ比べられます（1回ごとの値は一致しません）。

## 13. ランキングが変化した空港

### 条件を変えても安定な空港

- **ANC（アンカレッジ）・HND（羽田）**：13 条件すべてで上位 20（ANC は 1〜9 位、HND は 4〜14 位）。欠測の 3 モデルでも順位は 1 つも変わらない（ANC）か ±1 以内（HND）です。どちらも T1 の便の割合が高く、ティアを変えても周辺の小空港とのつながりが残ります。
- **PER（パース）**：ティア以外の条件と欠測のすべてで 1〜2 位です。T1 のみ・閾値 1 では 69 位まで下がります。
- **MNL・YVR・GRU・DFW・ORD**：全条件で 45 位以内にとどまります。

### 条件で大きく変わる空港

- **ティアに依存**：BOG・PKX・SCL・PEK・LIM・PVG・JNB は、T1〜T4 では上位 25 に入りますが、T1 のみではネットワークから消えるか（影響 0 として 106〜127 位）、ほぼ最下位になります。これらの空港には T1 の便がほとんどありません。逆に T1 のみで上がるのは、LBG（136 → 34 位）、GFK（134 → 40 位）、HOU（112 → 23 位）など北米・欧州の空港です。T1 のみの上位 10 は ANC・OTZ・ORD・HND・DFW・HNL・ADL・IAD・TEB・TYS で、北米に偏ります。これは受信網の厚い地域の便だけを残した結果で、より正しい順位ではありません。
- **期間に依存（LIM）**：リマ（LIM）は 12 位ですが、前半（1〜15 日）では最下位（157 位、Spillover はほぼ 0）になります。LIM とペルー国内の空港を結ぶ便が、3月 22 日以降にしか記録されていないためです（10 日間で 354 便、うち 77% が T4）。基準の 12 位は、14 空港（うち 13 がペルー国内）が LIM とだけつながっていることによるもので、月の後半だけの観測に依存しています。
- **閾値・ティアに依存（SVO・OTZ）**：SVO は T1〜T3 で 92〜139 位まで下がります。OTZ（アラスカ）は基準で 30 位ですが、条件によって 2〜148 位と大きく動きます。

### 欠測に敏感な空港

- 一様・地域別の欠測で順位の幅（p05〜p95）が大きいのは、基準で 70〜150 位の空港です（TSV 94〜143 位、NOC 91〜139 位、CPH 70〜103 位など）。上位 30 の空港の幅は ±3 位程度です。
- 低頻度路線のモデルでは、CHC（99 位 → 75〜148 位）、GLA（72〜143 位）、HOU（84〜149 位）、BNA（75 位 → 64〜116 位）、OPO、SNN、SAW などが大きく動きます。少数便の路線が、ほかの空港への唯一の経路になっている空港です。
- 地域別のモデルで一様のモデルより幅が広がるのは、CAI（幅 7 → 27）、EZE（8 → 22）、CGB（5 → 18）、RAI（6 → 18）、CMN（11 → 22）などのアフリカ・南米の空港です。大陸ごとの平均の幅も、アフリカ（8.9 → 14.2）と南米（6.8 → 10.8）で広がり、北米（12.7 → 9.7）と欧州（14.8 → 13.6）では狭くなります。
- **注意**：データの大陸の対応表で、スペイン（ES）がアフリカになっています（`pipeline/research_web.py` が国ごとに最初の空港の大陸を使っており、スペインではカナリア諸島の空港が先に来るため）。このため地域別のモデルでは MAD・BCN などスペインの空港の便がアフリカの率（30%）で落ちています。MAD の幅が 8 → 19 に広がったのはこのためです。既存のデータは変更していません。
- **追記（Phase 9F）**：同じ原因で、ロシア（RU）全体も欧州になっていました（空港の多数はアジア側）。Phase 9F で大陸を空港ごとに決めるよう直し、地域別のモデル（厳密）を `march-missing-regional-exact-v2` として計算し直しました。MAD の幅は 12.4、BCN は 20.6 になり（修正前 18.5・27.6）、Spearman の範囲（0.984〜0.992）、「条件に依存」の空港（23）、アフリカ・南米で幅が広がるという結論は変わりません。詳しくは [phase9f-report.md](phase9f-report.md) の 1 節にあります。

## 14. Systemic と Spillover の順位差

- 全 3,883 空港では、Systemic と Spillover の Spearman は 0.68 です。ただし、これは Spillover が 0 の 2,484 空港（ほかの空港どうしの経路に関わらない末端の空港）の同順位によるものです。Systemic の上位 1,000 に限ると 0.95、上位 157 では 0.99 で、上位 50 は完全に一致します。上位の空港では、2 つの指標はほぼ同じ順位になります。
- Spillover が 0 の空港の中で Systemic が最も高いのは LIR（702 位）・ZAZ・VAR・RMO などで、上位 700 には入りません。
- 上位 100 の中の違いは 5〜14 位程度で、向きは次の 2 通りです。
  - **Systemic が相対的に高い（直接の接続が多く、迂回路もある大きなハブ）**：JFK（Systemic 94 位・Spillover 108 位）、LHR（69・76）、IAH（93・100）、LAX（89・96）、HKG（98・105）、FRA（60・66）、CDG（39・44）。LAX・HKG・YYZ は止めても行けなくなる組が 0 で、効率の低下は経路が長くなる分だけです。
  - **Spillover が相対的に高い（直接の接続は少ないが、周辺の空港群の唯一の出入口）**：NOC（103・94）、TOS（104・97）、FAI（90・83）、LAD（91・85）、CNS（100・93）、DRW、YWG、TRD。直接の接続は 24〜93 空港ですが、止めると 1.8 万〜3.3 万組が行けなくなります。
- 便数の多い空港は、どちらの指標でも上位ではありません。便数 1 位の ORD は 25〜28 位、ATL は 52〜54 位、LAX は 89〜96 位です。どちらの指標も、迂回路のない周辺のネットワークへの出入口（PER・BOG・ANC など）を高く評価します。

## 18. 研究上の限界

- **近似の誤差**：世界規模のネットワークでは、256 起点の近似の順位誤差が大きく（9 節）、条件や試行による違いと区別できません。主な結論は厳密計算に基づいていますが、厳密計算の候補は上位 157 空港に限られます。
- **欠測モデルは仮定**：地域別・低頻度路線の確率は、受信網の品質の調査を参考にした仮定です。欠測の試行のばらつきは、そのモデルが正しい場合のばらつきで、信頼区間ではありません。実際の観測の欠けは、地域・時間帯・機材に偏り、便どうしも独立ではありません。
- **加えない**：観測されなかった便（受信網の外の路線）を推定して加えることはしていません。欠測モデルは「観測された便のうち一部が欠けていたら」だけを扱います。
- **重みなし・ホップ数**：効率はホップ数だけで、便数・座席数・距離・乗り継ぎ時間は使っていません。
- **単一空港の停止**：同時に複数の空港が止まる場合や、部分的な容量の低下は扱っていません。
- **1 か月だけ**：2026年3月だけの結果です。
- **T4 への依存**：アジア・南米では便の 6 割以上が便名からの推定（T4）で、ネットワークの形がその推定の正しさに依存します。
