# 過去のイベント：使い方（Phase 9G）

研究モードの「過去のイベント」タブで、EASA の紛争地域情報（CZIB）の各版の前後に、1090web で観測された便がどう変わったかを調べられます。計算方法は [historical-events-methodology.md](historical-events-methodology.md)、出典は [historical-event-sources.md](historical-event-sources.md) にあります。

勧告は運航者への注意喚起で、空域閉鎖・空港閉鎖ではありません。この機能は勧告によって空港や路線を止めることはしません。

## 基本の操作

1. 研究モードの「過去のイベント」を開きます（左の分析条件は使いません）。
2. **勧告**と**版**を選びます。保存版のない版は「取得できず」と表示され、選べません。
3. イベントの情報を確認します：題名と CZIB 番号、発行日・改訂日・有効期限・初めて確認した時刻、対象国と FIR、勧告の種類、出典（EASA のページ、検証の方法）、履歴の欠け。
4. **期間**（7・14・28・30 日または日数）と**便**（T1〜T4／T1〜T3 のみ）を選び、「**前後のネットワークを比較**」を押します（5〜15 秒）。

## 結果

- **観測された変化**：前後の期間（UTC の日付）、対象地域・A（地域内）・B（地域と地域外）・C（周辺国）・比較対象群・全便の 1 日の便数と変化率、観測された路線と空港の数、データ品質の警告。
- **イベントのタイムライン**：対象地域・周辺国・比較対象群の日別の推移（指数または便数）、各版の縦線（押すとその版を選ぶ）、前後の期間、収集停止の日。
- **時間的関係**：前の期間の傾き、比較対象群との比、プラセボ・チェック、差分の差分（条件を満たすときだけ）。
- **地図**：対象国の空港と、変化の大きい路線（減少・観測されなくなった・増加・後だけ観測）。「仮想停止」に切り替えると、対象国の空港を止めた場合に失われる路線を表示します。線は空港を結ぶ記号で、飛行経路ではありません。
- **空港・路線・航空会社**：変化の大きい順。行にカーソルを合わせると地図の空港が強調されます。
- **観測された変化と仮想停止の比較**：観測（全路線／対象地域の路線だけ変更）と仮想停止のネットワーク効率・到達可能性。
- **保存**：研究（JSON）、日別の推移（CSV）、路線の変化（CSV）、「実験で頑健性を確認」。

## 詳しい条件

イベント日の除外日数、路線を観測ありとする便数、旅客機のみ、収集停止の日を除くか、無向のネットワーク、周辺国と比較対象群（ISO の国コード）を変えられます。比較対象群は勧告の影響を受けない地域を選び、イベント前の推移が対象地域と平行かどうかを結果で確認してください。

## シミュレーションのタイムラインから

シミュレーションのタイムラインで「実際の安全勧告（EASA）」をオンにすると、表示中の期間に有効だった勧告が、シナリオの障害とは別の見た目（破線・斜線）で並びます。行や版の印を押すと、研究モードの「過去のイベント」でその版が開きます。勧告はシナリオに入らず、何も停止させません。

## 読むときの注意

- 結果は観測された ADS-B の便の比較で、勧告の効果ではありません。勧告は紛争・攻撃・空域閉鎖と同じ時期に出されます。
- 「後だけ観測された路線」は新規就航、「観測されなくなった路線」は廃止ではありません。
- 中東では便の多くが便名から空港を推定した便（T4）です。「T1〜T3 のみ」と比べてください。
- EASA の日付には時刻がなく、イベント日は前後どちらの期間にも入れていません。
- 保存した JSON には勧告の版と記録の版を記録します。記録が更新されても、保存した結果の対象は変わりません。
