# Research Mode の分析方法

Research Mode（研究モード）で使っている指標と計算条件をまとめます。実装：`src/research/`（指標は `graph.ts`、統計は `stats.ts`、条件は `model.ts`、集計は `network.ts`）。

**前提**：すべての値は「ADS-B で観測され、空港が判定できた航空会社コード付きの便」から作ったネットワークの構造指標です。実際の運航便数、旅客数、乗り継ぎ旅客、航空会社の採算、経済的な重要度を表すものではありません。

---

## 1. データ

| 入力 | 内容 |
| --- | --- |
| `public/data/<id>/months/YYYY-MM.json` | Explore Mode と同じ月別ファイル（路線 × 方向 × 航空会社コード × 旅客／貨物／不明 × 根拠 0/1） |
| `public/data/<id>/research-web/tiers/YYYY-MM.json` | 根拠 0 の便のうち T2・T3 の内訳（同じ路線 × 方向 × 航空会社コード × 分類） |
| `public/data/<id>/research-web/persistence.json` | 路線ごとに、データの月のうち1便以上あった月の数（根拠区分の組ごと） |
| `public/data/<id>/research-web/quality.json` | 版・入力のハッシュ、月別の根拠構成、異常日と収集停止（Phase 6B）、外部照合（Phase 7） |
| `public/data/<id>/research-web/manifest.json` | 各ファイルの SHA-256、元にした研究用ファイルの SHA-256 |

生成：`python pipeline/research_web.py --dataset observed-2026-v2`（`routes_monthly.parquet` と Phase 6B・7 の出力から作ります）。

**根拠区分の復元**：T4 ＝ Explore の根拠 1、T2・T3 ＝ 補助ファイル、T1 ＝ 根拠 0 − T2 − T3（分類ごと）。補助ファイルの値が Explore の値を超える場合は不整合として数えます（2026年データでは 0 件。テストで確認）。

## 2. 分析条件（`ResearchConfig`）

| 条件 | 既定 | 内容 |
| --- | --- | --- |
| 対象月 | 最新の月 | 1か月単位 |
| 対象地域 | 全世界 | 国（ISO 2文字）または大陸（AF・AS・EU・NA・OC・SA） |
| 接続の種類 | すべて | 地域を指定した場合：すべて＝その地域に関わる路線、国内＝両端がその地域、国際＝片端だけ。地域なし：国内＝両端が同じ国 |
| 空港 | なし | 指定した空港を発着する路線だけ（エゴネットワーク） |
| 航空会社コード | なし | ADS-B の便名の頭の文字。運航形態は表さない |
| 機材の分類 | 旅客・貨物・不明 | 機材の型式による分類 |
| 月間便数の下限 | **4** | 空港の組（往復の合計）の便数 |
| 観測月数の下限 | なし | 同じ根拠区分で1便以上あった月の数。データにない月は数えない（運休とみなさない） |
| 根拠区分 | **D（T1〜T4）** | A＝T1、B＝T1〜T2、C＝T1〜T3、D＝T1〜T4 |
| ネットワーク | 無向 | 有向＝観測された方向ごとの辺、無向＝空港の組（往復を合計） |
| 経路計算 | 自動 | 正確計算、または起点のサンプリング（起点の数・乱数シード） |

既定の根拠区分を D にしている理由：Phase 7 で、T1 だけに絞ると公式統計に比べて大きく過小になることを確認しています（米国国内線 −37%、ブラジル国内線 −90%）。T1 を「真実に最も近いネットワーク」として扱ってはいけません。

条件はすべて URL（`?mode=research&rm=…`）と出力 JSON に記録されます。同じ版のデータセットと同じ条件からは同じ結果になります（条件のハッシュ：正規化した JSON の FNV-1a、識別用）。

## 3. グラフの作り方

- ノード：条件を満たす路線を1本以上持つ空港。
- 辺：有向なら観測された方向ごと、無向なら空港の組。重み＝その月の観測便数（選んだ根拠区分と分類の合計）。
- 自己ループは除外（データセットにもない）、重複する辺は重みを合計してまとめます。
- 閾値：空港の組の往復合計が下限未満の路線を除きます（有向でも同じ組の単位）。
- **最短経路の長さはホップ数**（1路線 = 1）。便数を距離として使うことはありません。重み付きの最短経路は実装していません。

## 4. 指標

n はノード数、m は辺の数（無向の辺は1本と数える）。

| 指標 | 定義 | 正規化 | 参考 |
| --- | --- | --- | --- |
| 次数（接続先空港数） | 1路線以上でつながる異なる空港の数（有向では出入りのどちらか） | — | |
| 入次数・出次数 | 到着便のある空港の数、出発便のある空港の数（有向のみ） | — | |
| 次数中心性 | (入次数＋出次数) ÷ (n−1)。無向では 次数 ÷ (n−1) | (n−1) | NetworkX `degree_centrality` |
| 重み付き次数（強度） | 出発便＋到着便（無向では接続路線の便数の合計） | — | |
| 媒介中心性 | 他の空港 s, t の組の最短経路のうち、その空港を通るものの割合の合計（経路が複数ある場合は等分） | 有向：÷ (n−1)(n−2)、無向：÷ (n−1)(n−2)/2 | Brandes (2001)、NetworkX `betweenness_centrality` |
| 調和近接中心性 | Σ_{u≠v} 1 / d(u, v)（u から v へのホップ数、到達不能は 0） | ÷ (n−1) | NetworkX `harmonic_centrality`（正規化は本アプリ独自） |
| PageRank | 便数に比例した遷移、出辺のない空港は一様に移動、α = 0.85、L1 変化 < 1e-10 で停止 | 合計 1 | NetworkX `pagerank(weight=…)` |
| 連結成分 | 無向：連結成分、有向：弱連結成分と強連結成分（Tarjan） | — | |
| 密度 | 無向 2m / n(n−1)、有向 m / n(n−1) | — | |
| クラスタ係数 | 無向の単純グラフ（重みなし）で、隣接ノード対のうちつながっている割合。平均は全ノード（次数 1 以下は 0） | — | NetworkX `clustering`・`average_clustering` |
| 推移性 | 3 × 三角形の数 ÷ 連結した3つ組の数 | — | NetworkX `transitivity` |

有向ネットワークのクラスタ係数は、向きを無視した無向グラフで計算します。

### 媒介中心性・近接中心性の近似

- 「自動」では、n(n+m) ≤ 6×10⁸ なら正確計算（全起点の幅優先探索）、超える場合は起点のサンプリングに切り替えます。2026年の全世界ネットワーク（約 4,000 空港・10万方向別路線）は正確計算の範囲です。
- サンプリング：シード付きの擬似乱数（mulberry32）で起点を k 個、重複なしで選びます。媒介中心性は n/k 倍（Brandes & Pich 2007）、調和近接中心性は (n−1)/(v 以外の起点の数) 倍した推定値です。
- 近似を使った場合は、画面・出力 JSON に「近似」「アルゴリズム」「起点の数」「シード」「正規化方法」を記録します。近似値を厳密解として表示しません。

## 5. 順位と比較

- 順位：値の大きい順。同じ値は同じ順位（最上位の順位、"1224" 方式）。表示の並びは同じ値の中で空港 ID 順。
- 2つの条件の比較では、**変える条件は1つだけ**（月、閾値、根拠区分、地域）。変えた条件と同じ条件を必ず表示します。
- 上位20の比較：一致率（共通 ÷ 20）、Jaccard（共通 ÷ 和集合）、Spearman（平均順位のピアソン相関）、Kendall τb（同順位補正あり）。相関は両方の上位20の和集合について、それぞれの条件の全体の値（ない場合は 0）を使います。Phase 6B の Python 実装（`pipeline/analysis/network.py`）と同じ定義です。
- 前月比：データの前の月を同じ条件で集計した値との比較。前の月にない路線は「新規」と表示します。

## 6. 国・地域の集計

- 空港単位の絞り込みの後、各便を出発 → 到着の国（または大陸）の組に1回だけ数えます。同じ国の中の便は「国内」として別に数えます。
- 国どうしの便数は観測された航空機の移動で、旅客の流れや経済的な交流量ではありません。地域によって受信網の密度が違うため、地域どうしの比較には注意が必要です。

## 7. データ収集の停止（2026年5月）

- 月に収集停止（Phase 6B で全世界のギャップ時間が確認された日）がある場合、概要と比較で警告します。
- 表示するのは次の3つで、区別して示します。①観測便数そのまま、②暦日あたり（÷ 暦日数）、③全世界での「正常日あたり ÷ 暦日あたり」の差（実験的。Phase 6B の C2 方式）。
- ③は「停止した日も他の日と同じだった」という仮定に基づく参考値で、公式統計で確認された補正ではありません。分析対象のネットワークや公開データの便数は変更しません。異常日をすべて欠損として除く自動補正もしません。

## 8. 外部照合の表示

- 対象地域が米国・ブラジル・日本のとき、Phase 7 の照合結果のうち**同じ月・同じ根拠区分・同じ方向・同じ閾値**の行を表示します。
- 閾値が 1・4・10・30 以外の場合は最も近い下の値を使い、「閾値が違う」と明示します。月が照合されていない場合は値を出さず「この月の照合結果はありません」と表示します（参考として5月を除く全期間の値を折りたたんで示します）。
- 照合の条件と分析の条件の違い（航空会社照合、航空会社・分類・継続性・空港の絞り込み、接続の種類）は常に列挙します。
- その他の国は「未検証」と表示します。照合結果を「正解率」とは表現しません。

## 9. 出力

- CSV：空港（全指標）、路線、国・地域のネットワーク、概要、比較。各行に条件のハッシュ・データセット ID・版・対象月を入れます。
- JSON：データセットの ID・版・生成日時、入力のハッシュ、使用したファイルのハッシュ、すべての条件と条件のハッシュ、アルゴリズムとパラメータ、近似の有無、外部データの出典、計算日時、概要。比較中は比較の条件と変えた条件も記録します。
- JSON を読み込むと条件を復元します。データセットの ID・版が違う場合、条件のハッシュがファイルと一致しない場合、このデータセットにない値がある場合は警告します。
