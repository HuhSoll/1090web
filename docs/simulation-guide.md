# シミュレーションの使い方

空港や路線が使えなくなったと仮定して、航空ネットワークのつながりがどう変わるかを調べる機能です。複数の停止を時間軸に並べ、発生・終了・再開の順に再生できます。結果は観測データの構造分析で、欠航や運航の予測ではありません。計算方法は [simulation-methodology.md](simulation-methodology.md) にあります。

## いちばん簡単な使い方

1. 空港を検索するか、地図で空港をクリックします。
2. 詳細パネルの「この空港の停止をシミュレーション」を押します。
3. 右のパネルに影響の要約、下にシナリオのタイムライン、地図には失われた接続だけが表示されます。

基準期間は、そのとき地図に表示していた期間です。

## 画面の見方

| 場所 | 内容 |
| --- | --- |
| 右のパネル（上から） | 条件の1行（構造／時刻照合、期間の固定／時間窓に連動、期間、区分、有向）と意味の1文 → 重大な警告 → 影響の要約（4枚のカード） → 障害の内容（イベント一覧） → 折りたたみの詳細 |
| 下のタイムライン | 時刻のカーソル、イベントの帯、影響の時間変化の図、再生の操作 |
| 地図の左下 | 表示モード、「停止前を見る」、凡例 |

### 影響の要約（カードを押すと移動）

| カード | 意味 | 押すと |
| --- | --- | --- |
| 失われた直接接続 | 障害前の接続数 → 障害後（失われた数） | 地図に失われた接続だけを表示（もう一度で元に戻す） |
| 影響対象の観測便数 | 構造：使えない接続上の期間中の観測便／時刻照合：停止の時間に入る観測記録 | 内訳（詳細分析） |
| 経路がなくなった空港の組（波及） | 停止していない空港どうしで、障害前は経路があり障害後はない組 | その組の経路の比較 |
| 最も影響を受けたほかの空港 | ランキングで選んだ指標が最も大きい空港 | 影響空港の地図表示とランキング |

### 地図の表示モード

- **変化のみ**（既定）：失われた接続（オレンジの破線）と便数が減った接続だけ。停止した空港は赤い点、停止した路線は黄色。
- **前後を重ねる**：変化のない接続も薄く表示。
- **障害後**：仮想障害後のネットワーク。
- **影響空港**：停止していない空港を、ランキングの指標の大きさで表示。
- **停止前を見る**：押している間（または B キーを押している間）観測ネットワークを表示。短く押すと固定され、もう一度で戻ります。

カメラの位置はモードを変えても変わりません。ランキングやカードで空港を選ぶと、地図がその空港に移動します。

## 停止を追加・編集する

- 地図で空港を選び、「今から6時間停止」（シミュレーション時刻から 6 時間）または「期間中ずっと停止」。
- 路線を選ぶと「この路線を今から停止（双方向、6時間）」や片方向の停止。
- タイムラインの帯をドラッグすると移動、両端をドラッグすると開始・終了を変更（1時間単位、Alt キーで15分単位）。
- 帯や一覧の名前を押すと編集欄が開き、開始・終了を UTC で正確に入力できます。名前、出発・到着の別、出典（仮想／報告済み）、有効・無効、複製、削除もここで変更します。終了時刻はその時刻を含みません（12:00〜18:00 の停止は 18:00 には停止していません）。
- 間違えたら「元に戻す」（Ctrl+Z）、「やり直す」（Ctrl+Shift+Z）。

報告済みの実際の出来事として登録するときは、出典を必ず入力してください。安全勧告は閉鎖ではないので、登録しても何も停止しません。

## 時間を動かす

- タイムラインをクリック・ドラッグするとシミュレーション時刻が動きます。時刻欄に直接入力もできます。
- ⏮ ⏭ で前後のイベントの開始・終了へジャンプ、◀ ▶ で1ステップ（1時間・6時間・1日）移動、▶ で再生。
- 「拡大」「縮小」「全体」で表示範囲を変えます。
- 再生中は軽い指標（失われた接続、影響対象の便）だけを更新し、接続性（経路のない組など）は止めたときに計算します。

## 条件（詳細設定）

| 設定 | 内容 |
| --- | --- |
| 分析方式 | 構造：シミュレーション時刻に停止しているものを使えないと仮定／時刻照合：便の記録の時刻が停止の時間に入るものだけを除く |
| 基準ネットワーク | 期間を固定：観測ネットワークは変わらず、変わるのは停止だけ／時間窓に連動：各時刻の観測の時間窓（タイムラインで 1日・直近24/6/1時間を選択）と比べる |
| 基準期間 | 固定のときの期間（UTC） |
| 根拠区分・最低便数・有向・時刻の基準 | 基準ネットワークを作る条件 |
| 空港での時刻 | 時刻照合のとき。出発は航跡開始・到着は航跡終了（既定）、または基準時刻 |

## 詳細を調べる

- **影響を受けた空港**：到達できなくなった空港・2ホップ以内の減少・直接接続の減少のどれかで並べたランキング。行を押すと地図が移動し、「経路と原因」が開きます。
- **経路と原因**：選んだ空港が到達できなくなった相手・経路が長くなった相手。相手を押すと、障害前後の経路、元の経路に含まれていた停止空港、つながらなくなった区間を表示し、地図に経路を描きます。「イベントごとに確認」で、各イベントを1つ除いた場合の経路も確かめられます（構造のみ）。
- **詳細分析**：全体と波及の到達可能性・効率・連結成分、イベントを1つずつ除いた比較、便の内訳（航空会社・地域・時刻の根拠）、時系列の計算。

## 保存・共有・出力

- シナリオを保存（JSON）／読み込み：イベント、時刻、ステップ、条件が戻ります。Phase 9C のファイルも読めます。
- リンクをコピー：短いシナリオは URL に入ります。
- イベント一覧・時系列・指標・空港別・路線別・失われた経路・地域別（CSV）、結果（JSON）。
- 「{時刻} の状態を Research Mode で分析」：その時刻の障害後のネットワークで中心性などを計算し、観測ネットワークや「1つのイベントを除いた同じシナリオ」と比べます。

## 注意

- 2026年5月5〜7日はデータ収集が止まっていた疑いがあり、警告が出ます。この期間の便の少なさは観測の欠落で、障害の影響には数えません。
- 停止が終わると接続は基準の状態に戻ります。仮想的な制限の解除で、便が回復する速さの予測ではありません。
- 2ホップ・3ホップの到達や代替経路は空港どうしのつながりで、乗り継ぎ便があることを意味しません。
- 複数のイベントが重なるとき、1つのイベントを原因とは断定しません。イベント別の差を足しても全体の影響にはなりません。
- シミュレーションを閉じる（× または上部の「シミュレーション」）と、地図は観測ネットワークの表示に戻ります。
