# 過去のイベント：計算方法（Phase 9G）

研究モードの「過去のイベント」と `pipeline/events/` の計算方法です。使い方は [historical-events-guide.md](historical-events-guide.md)、データの出典は [historical-event-sources.md](historical-event-sources.md)、結果は [phase9g-report.md](phase9g-report.md) にあります。

目的は、安全勧告の発表・改訂と、観測された航空ネットワークの変化の**時間的な関係**を調べることです。因果関係は決めません。

## 1. 勧告の記録

### 1.1 単位と識別子

- 勧告：`bulletinId`（EASA の CZIB 番号、例 `2026-03`）
- 版：`revisionId`（`R0` が最初の版、改訂ごとに `R1`、`R2` …）
- 1 つの版を 1 件の記録とし、改訂で上書きしません。

### 1.2 日時

| 項目 | 意味 | 由来 |
| --- | --- | --- |
| `issueDate` | 勧告の最初の発行日 | ページの「Issue date」 |
| `revisionDate` | その版の改訂日（R0 はなし） | 「Revision date」 |
| `effectiveDate` | 分析でイベント日とする日（R0 は発行日、それ以外は改訂日） | 上の 2 つ |
| `validUntil` | その版の有効期限 | 「Valid until」 |
| `validFrom` | 常に `null`（EASA は開始を明記しない） | — |
| `publicationTimestamp` | 常に `null`（公表の時刻は不明） | — |
| `firstSeenAt` | その版を最初に確認した時刻（UTC）。公表時刻の上限にすぎない | 最も早い保存版・取得 |

EASA の日付は現地（ドイツ）の日付で、時刻がありません。不明な日時は推測で埋めません。

### 1.3 内容

対象国（`coveredCountries`。ない版は空域の説明に書かれた国 `countriesNamedInAirspace`）、空域の説明（`coveredAirspace`）、FIR の ICAO コード（`firs`）、勧告の種類（`recommendationType`：運航しないこと／注意して運航／リスク評価／高度の指定。勧告の文の語句による）、勧告の要約、対象の運航者、出典の URL、すべての保存版・取得（時刻・URL・SHA-256）、検証の方法（`verificationStatus`）。

すべての記録は `kind: "safety-advisory"`、`isClosure: false` です。

### 1.4 履歴の作り方

1. EASA の現行のページ（勧告のノードごと）とエクスポートを取得します。
2. Internet Archive の CDX で、各勧告の URL（`czibs/2026-03*` など）の保存版を探し、内容の違うもの（digest ごと）を取得します。
3. 各ページから CZIB 番号を読み、（勧告, 版）ごとにまとめます。最も早い保存版の内容を記録とし、ほかは証拠として残します。保存版の間で内容が違う場合は `contentVariants` で示します。
4. 番号の途中で保存版のない版は `missingRevisions` に入れ、内容を補いません。
5. CZIB 番号のないページ（エラーページなど）、出典やチェックサムのない記録は除外します。

記録全体のハッシュを `recordsVersion` とし、研究の結果に記録します。

## 2. 対象地域

- 勧告の対象は空域（FIR・飛行高度）です。1090web には飛行経路がないため、**空港の所在国**で便を選びます。両者は同じ範囲ではありません。
- 国は版の対象国の欄から取り、ない場合は空域の説明に書かれた国名を使います（根拠を表示）。FIR だけが書かれた版では国を推測せず、対象国なしとします。
- 便の区分：
  - A：両端が対象国
  - B：一端が対象国、もう一端が地域外
  - C：周辺国（指定した国）に出入りし、対象国に出入りしない
  - 比較対象群：指定した国に出入りし、対象国・周辺国に出入りしない
- 地図の線は空港を結ぶ記号で、勧告の空域を通過したかどうかは判断しません。

## 3. 前後の比較

- 日は UTC の日で、便は基準時刻（航跡の開始、なければ終了）で数えます（Phase 9A と同じ）。
- イベント日 E は `effectiveDate` の 00:00 UTC です。公表の時刻がわからないため、E の 1 日は既定で前後どちらにも入れません。
  - 前：[E − n 日, E)
  - 後：[E + 1 日, E + 1 + n 日)
- n は 7・14・28・30 日または任意。7・14・28 日は前後の曜日の構成がそろいます。30 日などでは構成が違うことを警告します。
- 観測データの外にはみ出す期間は短くし（補完しない）、警告します。
- 収集停止（Phase 6B・9A の `collection_gap`）の日は、既定で日別の統計から除きます。

### 指標

- 系列ごとの 1 日平均の便数と変化率
- 観測された路線（期間中に指定の便数以上）、後だけ観測された路線、観測されなくなった路線、観測便数が増えた・減った路線（1 日の便数が 1.5 倍以上かつ 0.5 便以上の差）
- 空港別の 1 日の便数と接続先の数、航空会社別の 1 日の便数（対象国に出入りする便）
- 観測された空港数

「後だけ観測された路線」は新規就航、「観測されなくなった路線」は廃止を意味しません。

## 4. 時間的関係

- **イベント前の傾き**：前の期間の log(便数 + 1) を日に回帰した傾き（最小二乗法）と t 値。期間全体での変化 exp(傾き × (日数 − 1)) − 1 を示します。|t| ≥ 2 なら、勧告の前から変化していたと読みます。
- **比の傾き**：log((対象地域 + 1) / (比較対象群 + 1)) の前の期間の傾き。
- **プラセボ**：イベント日より 7 日ずつ前の日を仮のイベント日とし、同じ比較をします。仮の比較の後の期間は実際のイベント日より前に終わる必要があり（勧告後の日を含めない）、前の期間はデータの中に収まる必要があります。最大 12 日。
- **差分の差分**：log の差（対象地域の変化 − 比較対象群の変化）。次のすべてを満たすときだけ値を示します。
  1. 前後とも完全な 14 日以上の期間
  2. 曜日の構成が同じ
  3. 期間に収集停止がない
  4. 比較対象群が 1 日 30 便以上
  5. 比の前の期間の傾きが 0 と区別できない（|t| < 2）
  6. プラセボが 3 日以上あり、すべて実際の差より小さい

  満たしても、平行トレンドの仮定のもとでの推定で、仮定は証明されません。満たさない場合は単純な差を「記述的な値」として示します。

## 5. 仮想停止との比較

Phase 9C の影響計算（`src/simulation/impact.ts`、`impactInputOf`）を使います。節点は前の期間のネットワークの空港、対象は対象国の空港です。

| 比較 | 後のネットワーク |
| --- | --- |
| 観測（全路線） | 後の期間のネットワーク。世界中の変化がすべて入る |
| 観測（対象地域の路線だけ変更） | 前の期間のネットワークのうち、対象国の空港に出入りする路線だけを後の期間のものに置き換えたもの |
| 仮想停止 | 前の期間のネットワークから、対象国の空港の路線をすべて除いたもの（構造的な閉鎖） |

接続数、接続のある空港、ネットワーク効率、ほかの空港どうしの効率と到達できる組、経路がなくなる組を比べます。仮想停止は運航者の実際の対応ではなく、勧告は閉鎖ではありません。

## 6. 頑健性

- ティア：T1〜T4 と T1〜T3 のみを切り替えられ、対象地域の T4 の割合が半分を超えると警告します。
- 路線の便数の閾値、旅客機のみ、無向、収集停止の除外を変えられます。
- 「実験で頑健性を確認」で、前の期間と対象国の空港（便数の多い 30 空港まで）を Phase 9E の実験に渡し、ティア・閾値などの感度分析ができます。
