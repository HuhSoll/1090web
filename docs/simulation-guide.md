# シミュレーションの使い方

空港や路線が使えなくなったと仮定して、航空ネットワークのつながりがどう変わるかを調べる機能です。結果は観測データの構造分析で、欠航や運航の予測ではありません。計算方法の詳細は [simulation-methodology.md](simulation-methodology.md) にあります。

## いちばん簡単な使い方

1. 空港を検索するか、地図で空港をクリックします。
2. 詳細パネルの「この空港の停止をシミュレーション」を押します。
3. 右側にシミュレーションのパネルが開き、結果が表示されます（1日分で約2秒）。

基準期間は、そのとき地図に表示していた期間（月、または時間窓）です。

## パネルの見方

- **障害の内容**：停止している空港・路線。チェックを外すと一時的に無効、× で削除します。
- **地図の表示**：「前後を重ねる」「障害後」「障害前」。重ねる表示では、失われた接続がオレンジの破線、変わらない接続が薄い線、停止した空港が赤い点、停止した路線が黄色の線です。
- **直接の影響**：失われた接続、接続を失ったほかの空港、影響対象の観測便数など。
- **接続性**：ネットワーク全体と、停止した空港以外への「波及」を分けて表示します。
- **影響の大きいほかの空港**：行をクリックすると、その空港が到達できなくなった相手や、経路が長くなった相手が表示されます。相手を押すと、障害前後の経路が地図とパネルに出ます。

## 空港・路線を追加する

- 空港：地図でクリック →「この空港を停止」。複数の空港を続けて追加できます。
- 路線：地図で路線をクリック →「この路線を停止（双方向）」、または片方向のボタン。
- 外す：同じ空港・路線を選んで「障害の対象から外す」。

## 詳細設定

| 設定 | 内容 |
| --- | --- |
| 分析方式 | 構造：期間中ずっと使えないと仮定／時刻照合：便の記録の時刻が障害の時間に入るものだけを除く |
| 基準ネットワーク | 期間を固定／時間窓に連動（タイムラインで日時を動かすと、各期間で計算し直します） |
| 基準期間 | 固定のときの期間（UTC）。「地図に表示中の期間を使う」で今の表示に合わせます |
| 評価時刻 | 構造・固定のとき、その時刻に有効なイベントだけを適用（◀ ▶ で1時間ずつ） |
| 障害の時間 | 各イベントの開始・終了（UTC、分単位、終了時刻は含まない）。空欄は期間中ずっと |
| 空港の発着 | 出発と到着／出発のみ／到着のみ |
| 根拠区分・最低観測便数・有向・時刻の基準 | 基準ネットワークを作る条件 |
| 空港での時刻 | 時刻照合のとき。出発は航跡開始・到着は航跡終了（既定）、または両方とも基準時刻 |

時刻照合では、「出発・到着の時刻で照合した場合」と「基準時刻で照合した場合」の便数を並べて表示します。

## 保存・共有・出力

- シナリオを保存（JSON）／読み込み：同じ条件と結果を再現できます。データセットの版が違うと警告が出ます。
- リンクをコピー：短いシナリオは URL に入ります。長いものは JSON で共有してください。
- 結果（JSON）、ネットワーク指標・空港別・路線別・失われた経路・地域別（CSV）。CSV の各行にシナリオのハッシュと期間が入ります。
- 「Research Mode で分析」：障害後のネットワークで中心性などを計算し、比較タブで障害前（観測）と比べます。

## 注意

- 2026年5月5〜7日はデータ収集が止まっていた疑いがあり、警告が出ます。この期間に便が少ないのは観測の欠落です。
- 2ホップ・3ホップの到達や代替経路は、空港どうしのつながりを表すだけで、乗り継ぎ便があることを意味しません。
- シミュレーションを閉じる（× または上部の「シミュレーション」）と、地図は観測ネットワークの表示に戻ります。
