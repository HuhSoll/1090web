# イベント調査：計算方法（Phase 9H）

実際の出来事（安全勧告、空域制限・閉鎖、空港閉鎖、安全保障上の出来事、再開）を、出典に書かれたとおりに記録します。そのうえで、観測された便と同じ時間軸に並べる方法を説明します。前後比較の計算は Phase 9G と同じです（[historical-events-methodology.md](historical-events-methodology.md)）。

## 1. イベントの記録

### 1.1 種類

| 種類 | 意味 | タイムラインのレイヤー |
| --- | --- | --- |
| `SECURITY_INCIDENT` | 攻撃などの安全保障上の出来事 | A |
| `OTHER_VERIFIED_EVENT` | ほかの確認できた出来事（停戦など） | A |
| `AIRSPACE_RESTRICTION` | 空域の制限（運航者・高度・機材の限定を含む） | B |
| `AIRSPACE_CLOSURE` | 空域の閉鎖 | B |
| `AIRPORT_CLOSURE` | 空港の閉鎖・運航停止 | B |
| `AIRSPACE_REOPENING` | 再開。再開の対象となるイベントを `reopens` の関係で必ず示す | B |
| `SAFETY_ADVISORY` | 安全勧告（EASA CZIB、FAA の KICZ NOTAM など） | C |

閉鎖・制限には範囲（`closureScope`）を付けます：全面、部分、機材限定、運航者限定、不明。勧告や運航者限定の制限は閉鎖ではありません。

### 1.2 時刻

時刻は 5 つを分けて持ち、1 つにまとめません。

- 発生（`occurrence`）：出来事が起きた時刻
- 発表（`publication`）：文書・記事が出た時刻
- 有効の開始（`effectiveFrom`）・有効の終了（`effectiveUntil`）
- 資料で初めて確認（`firstVerifiedAt`）：出典のうち最も早い保存・取得の時刻。発表時刻の上限にすぎない

1 つの時刻に出典が複数あれば、値をすべて残します。各値には次を付けます。

- 精度：分、時、日付、月、不明
- 現地時刻と時間帯
- 根拠（たとえば「記事の公開時刻：発表の上限」）
- 出典の ID

規則は次のとおりです。

- **日付だけの時刻には UTC を付けません。** 00:00 UTC に置くことはしません。パイプラインがそのような記録を除外し、ブラウザ側でも除外します。
- 時刻ありの値は、現地時刻と UTC が 1 分以内で一致するかを確かめます。
- 不明な時刻は「不明（補完していません）」と表示し、位置を持たせません。

### 1.3 日付の範囲

日付だけの時刻は、その現地の 1 日全体（24 時間）とします。

- 固定の時差の地域（Asia/Dubai +4、Asia/Qatar・Asia/Kuwait・Asia/Riyadh +3、Asia/Tehran +3:30）は、時差を引いた UTC の範囲を使います。たとえば Asia/Dubai の 2026-02-28 は 2026-02-27T20:00Z〜02-28T20:00Z です。
- 時間帯が不明な日付と、夏時間のある地域（Europe/Berlin など）の日付は、UTC の 1 日として扱い、「時差が不確か」とします。夏時間の時差は推定しません。

イベントの開始は、発生、有効の開始、発表の順に、最初にわかる値の最も早い範囲を使います。終了は有効の終了の最も遅い値です。終了が不明な場合は次のように扱います。

- 安全保障上の出来事、そのほかの出来事、再開は、その日（その時刻）だけとします。
- 制限・閉鎖・勧告は「有効のまま」とし、タイムラインでは「…」を付けます。

同じ時刻の出典の値どうしが 1 日以上離れていれば「資料間で時刻が違う」と表示します。

### 1.4 対象

国（ISO 2 文字）、FIR（ICAO）、空港（ICAO）、高度、運航者、機材を分けて持ちます。

- 運航者の範囲は 4 種類です：すべて、米国の運航者、EASA の運航者、指定。FAA の SFAR と KICZ NOTAM は米国の運航者だけが対象で、空域全体の閉鎖ではありません。
- 高度の制限は、出典の表現のまま残します（SFAR 77 の「FL320 未満」など）。

### 1.5 検証状態

| 状態 | 条件 |
| --- | --- |
| 検証済み | 当局の文書（またはその保存版）で確認できる |
| 一部検証 | 当局の文書・国営通信で一部を確認できる（たとえば EASA の文面に書かれた攻撃） |
| 資料間に矛盾 | 出典どうしで内容・時刻が食い違う |
| 不完全 | 出典はあるが、時刻や範囲の重要な部分が欠けている |
| 未検証 | 報道だけ |

出典の種類で上限が決まります。報道だけのイベントは「未検証」にしかできず、「検証済み」には当局の文書が必要です。パイプラインとブラウザの両方で確かめます。

各イベントには「出典で確認できること」と「確認できないこと」を別々に書きます。

### 1.6 関係

イベントどうしの関係は、出典が述べている場合だけ `basis: source` として記録します。例：再開とその対象、空港の停止とその原因の閉鎖。

詳細画面では、前後 3 日のほかのイベントも表示しますが、これは「時間的に近いだけ」とします。それ以前から有効なイベントには「それ以前から有効」と付けます。時間的に近いことは関係でも原因でもありません。

### 1.7 CZIB との互換

Phase 9G の CZIB の履歴（`easa-czib-history.json`）はそのまま残し、ブラウザで各版を安全勧告に変換します。

- ID：`CZIB:<勧告>/<版>`
- 発表：EASA の日付（Europe/Berlin、日付のみ）
- 有効の終了：次の版の日付か有効期限の早いほう
- 運航者：EASA の運航者
- 前の版：`supersedesEventId`

研究の保存 JSON は、CZIB では 9G と同じ形式です。

## 2. 記録の作り方

1. `pipeline/events/sources.json` に出典を書きます（URL、発行元、種類、保存版なら保存時刻）。
2. `fetch_sources.py` で文書を `data/raw/events/sources/` にダウンロードします。HTTP ステータス、取得時刻、SHA-256 を `sources-documents.lock.json` に記録します。取得できなかった出典も理由とともに残します。
3. 出典を読み、`pipeline/events/curated/*.json` にイベントを書きます。時刻ごとに出典の ID と根拠を付けます。確認できなかった事柄は `notCaptured` に書きます。
4. `build_registry.py` で検証し、`public/data/events/events.json` を書き出します。検証を通らない記録は、理由とともに `rejected` に入れます。記録の版（`registryVersion`）は内容の SHA-256 の先頭 12 桁です。

自動で取り込むイベントはありません。報道の見出しなどからイベントを作ることもしません。

## 3. 前後比較

Phase 9G の比較（`runStudy`）を、イベントを「研究の対象」（`StudySubject`）にして実行します。

- **イベント日**
  - 日付だけのイベント：現地の日付を UTC の日として使い、前後の期間からは除きます。
  - 時刻のあるイベント：その UTC の日を使います。
  - CZIB では 9G と同じく EASA の日付を使います。
- **対象地域**：イベントの国です。CZIB では 9G と同じく EASA の国の欄（なければ空域の記述）を使います。国の指定がないイベント（FIR だけの FAA の NOTAM など）は比較できません。
- **警告**：イベントが「検証済み」でなければ「このイベントは完全には検証されていません」と表示します。
- **比較期間のイベント**
  - 前、イベント日、後の各期間について、その期間に有効だった・起きたイベントのうち、対象地域の国または FIR に関わるものを一覧にします。
  - 日付だけのイベントが時差のために期間の端に 1 日未満だけ重なる場合は、「時差で数時間だけ重なる」と示します。
  - この一覧は状況の説明で、計算には使いません。
- **キャッシュ**：結果はイベントと条件の組ごとにメモリに保存し、同じ条件では再計算しません。

ほかの手順（前後の比較、事前トレンド、プラセボ、DiD の 6 条件、路線・空港・航空会社の変化、仮想停止との比較）は 9G と同じです。どの値も、イベントの効果を示すものではありません。

## 4. 統合タイムライン

| レイヤー | 内容 |
| --- | --- |
| A 安全保障 | `SECURITY_INCIDENT`、`OTHER_VERIFIED_EVENT` |
| B 制限・閉鎖 | 制限、閉鎖、空港閉鎖、再開 |
| C 勧告 | `SAFETY_ADVISORY`（CZIB を含む） |
| D 観測便数 | 比較を実行したときの対象地域の日別便数 |
| E 仮想 | シミュレーションのシナリオのイベント（実際の出来事ではない） |

時刻の精度などは、次のように描き分けます。

- 時刻ありは実線、日付だけは 1 日幅の斜線、報道だけは破線です。
- 終了が不明なものは「…」で示します。
- 同じレイヤーで重なる棒は別の行に並べます。
- 2 つ以上のイベントが同時に有効な期間は、上部の帯で示します。
