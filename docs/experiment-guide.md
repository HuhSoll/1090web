# 実験の使い方（研究モード）

研究モードの「実験」タブでは、空港を1つずつ止めたときの影響の順位が、ネットワークの作り方や観測の欠けでどれだけ変わるかを調べられます。計算方法は [experiment-methodology.md](experiment-methodology.md) にあります。

## いちばん簡単な使い方

1. 右上の「研究」に切り替え、左の「分析条件」で期間（月または時間窓）を選びます。
2. 上のタブで「実験」を開きます。
3. 「感度分析」と「かんたん」のまま、条件「ティア × 閾値（9）」で「実験を実行」を押します。

接続数の上位 30 空港を候補に、9 つの条件でそれぞれ全候補を止めて計算します。

- 実行前に、実行回数・候補数・経路探索の回数・おおよその時間を表示します。
- 計算中は進み具合と残り時間を表示します。「取り消す」で止めると、終わった回だけで結果を作り、「未完了」と表示します。

## シミュレーションから始める

シミュレーションで空港を止めたあと、右のパネルの書き出しの欄にある「この結果の頑健性を検証」を押します。

- シナリオの期間・ティア・区分・閾値で「実験」タブが開きます。
- 止めた空港は必ず候補に入り、結果では色を変えて表示されます。
- 路線や航空会社の停止は単一空港の停止ではないので候補に入りません（件数を表示します）。
- 基準は観測ネットワークです（シナリオは適用しません）。シナリオを適用したネットワーク上で実験したい場合は、シミュレーションの「Research Mode で分析」から入り、その条件のまま「実験」タブを開きます。

## 実験の種類

| 種類 | 何を変えるか | 空港の集合 |
| --- | --- | --- |
| 感度分析 | ティア、閾値、有向・無向、機材の区分 | 条件ごとに変わる |
| 欠測 | 便を想定したモデルでランダムに取り除く（10 回または 30 回） | 基準のまま固定 |

欠測のモデル：

- **A 一様**：すべての便が同じ確率で欠けます。
- **B 地域別**：大陸ごとの確率と、出発地・到着地の組み合わせ方（高いほう／どちらかで欠測／両方で欠測／出発地のみ／到着地のみ）を指定します。
- **C 低頻度路線**：基準ネットワークで便数が閾値未満の路線の便を欠けやすくします。便ごとに欠けるか、路線ごとまとめて消えるかを選べます。

## 詳細設定

「詳細」に切り替えると、次を変えられます。

- 候補の空港：接続数の上位 10 / 30 / 50 / 100、またはすべて
- 経路の計算：256 / 1,024（既定）/ 2,048 空港のサンプル、または厳密（全空港）。世界全体のネットワークでは 256 起点だと上位の順位の誤差が大きいため、順位を比べるときは 1,024 以上か厳密を使ってください（[phase9e-report.md](phase9e-report.md) の 9 節）
- グラフ：有向（既定）／無向
- 乱数シード、起点サンプルのシード

同じ定義・同じシードなら、何度実行しても同じ結果になります。

## 結果の見方

上の「波及／全体」で、どちらの影響の順位を見るかを切り替えます。

- **波及（Spillover）**：ほかの空港どうしの行き来がその空港にどれだけ頼っていたか。
- **全体（Systemic）**：止めた空港自身の行き来も含めた全体の効率の低下。

| 表示 | 内容 |
| --- | --- |
| 概要 | 実行回数、候補数、全体と波及の順位の一致度、上位で安定した空港の数、条件・試行ごとの基準との一致（Spearman、Kendall、上位 k の重なり、Jaccard） |
| 順位の比較 | 基準と、選んだ条件・試行の順位を空港ごとに並べた表 |
| 安定性 | 空港ごとの順位の中央値・p05〜p95・標準偏差・上位 k に入った割合と、「安定／条件に依存」の区分 |
| 影響の分布 | 上位の空港の影響の箱ひげ図（箱 p25〜p75、線は中央値、ひげ p05〜p95、点は基準） |
| 地理 | 世界地図上の候補の空港を、順位の幅・上位に入った割合・基準の影響・選んだ回での順位の変化で色分け。凡例に数値の目盛り。大陸ごとの平均 |
| 詳細 | 実行ごとのネットワークの大きさ・計算方法・時間・完了、選んだ空港の値、実験の定義（JSON）、書き出し |

表の行や地図の点をクリックすると空港を選択し、「地図で表示」で Explore の地図に表示します。

### 読むときの注意

- 分位点は実行の分布を示すもので、信頼区間ではありません。
- 欠測の実験のばらつきは、想定したモデルのもとでのばらつきです。
- T1 のみは厳しい条件というだけで、より正確なネットワークではありません。アジア・南米・アフリカの主要空港の多くは T1 の便がなく、この条件では消えます。
- 起点をサンプルした場合（近似）、値には経路計算のサンプリング誤差も含まれます。

## 書き出しと Python のバッチ

- 「詳細」の表示から、結果（JSON）、実行ごとの順位（CSV）、空港ごとの統計（CSV）を保存できます。
- 「バッチ用の定義」は、同じ実験を Python のバッチで実行するための定義ファイル（JSON）を保存します。100 回以上の試行や全空港の厳密計算はこちらを使います。
  - 国・航空会社・空港・国内／国際の指定、継続月数の閾値、シナリオを含む条件は書き出せません（理由を表示します）。

```bash
cd pipeline
../.venv/Scripts/python.exe -m experiments.run <定義.json> --out ../data/experiments/<名前> --workers 11
```

- `--resume` を付けると、途中で止まった実行の続きから計算します（候補 48 件ごとに保存しています）。
- 出力：`result.json`（研究モードで読み込める形式）、`rankings.csv`、実行ごとの記録（`runs/`）、途中経過（`chunks/`）。
- 出力先の `data/experiments/` は Git の管理外です。

「バッチ結果を読み込む」で `result.json` を選ぶと、ブラウザで計算した結果と同じ画面で見られます。

- ファイルはこのコンピューターから読み込むだけで、アップロードはしません。64 MB までです。
- 形式やデータセットのバージョンを確認し、違う場合や未完了・近似の場合は警告を表示します。
