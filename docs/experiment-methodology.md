# 実験の計算方法（Phase 9E）

研究モードの「実験」と Python のバッチ（`pipeline/experiments/`）が使う計算方法をまとめます。どちらも同じ定義・同じ手順で計算し、テストで突き合わせています。使い方は [experiment-guide.md](experiment-guide.md) にあります。

この実験の目的は「重要な空港」を決めることではありません。どの結論が条件を変えても変わらず、どの結論がネットワークの作り方や観測の欠けに左右されるかを分けることです。

## 1. 何を測るか

候補の空港 v を **1つだけ** 止めたとき、ネットワーク効率がどれだけ下がるかを測ります。止めるとは、v に出入りするすべての接続を取り除くことです。

ネットワーク効率は、順序付きの空港の組 (s, t) について 1/d(s, t) を平均した値です。

- d はホップ数（重みなし）
- 経路がない組は 1/d = 0
- 有向グラフが既定、無向は感度分析の条件の1つ

### Systemic（全体）

- 空港の集合 V（n 空港）は固定します。止めた空港は孤立したノードとして残ります。
- 前後とも n(n−1) 組の平均です。
- 止めた空港自身の組（v から・v への）も含むため、v 自身の接続の多さが大きく効きます。

### Spillover（波及）

- 空港の集合は V \ {v}（前後とも同じ）、(n−1)(n−2) 組の平均です。
- 「前」は全ネットワークでの距離で、v を通る経路を含みます。「後」は v を通れません。
- ほかの空港どうしの行き来が v にどれだけ頼っていたかを表します。

主な指標は Spillover の効率の低下です。あわせて次も記録します。

| 指標 | 意味 |
| --- | --- |
| systemicDrop / spilloverDrop | 効率の低下（前 − 後） |
| spilloverBefore | Spillover の「前」の効率 |
| unreachablePairs | 前は経路があり、後はなくなるほかの空港どうしの組の数 |
| hop1Drop / hop2Drop / hop3Drop | Spillover の組のうち 1・2・3 ホップ以内で行ける組の割合の低下 |
| directLost | v と直接つながっていた空港の数（入・出の区別なし） |
| flightsLost | v の接続上の便数 |

定義は Phase 9C のシミュレーション（`src/simulation/impact.ts`）と同じで、空港を1つ止めたシナリオとすべての候補で一致することをテストしています。

## 2. ネットワークの作り方

研究モードの `buildResearchNetwork` と Python の `experiments/data.py` は同じ規則でネットワークを作ります。

1. 便を、空港の判定ティア（T1〜T4 のどれを使うか）・機材の区分・時刻の基準・地域で絞ります。
2. 空港の組（両方向の合計）の便数が閾値（minFlights）以上なら残します。
3. 有向では、便がある向きごとに弧を1本置きます。無向では組ごとに辺を1本置きます。
4. 残った組に現れる空港がノードです。

## 3. 感度分析

基準の条件から1つ以上の項目を変えた条件ごとに、ネットワークを作り直して全候補を評価します。

- 変えられる項目：ティア（T1〜T4 / T1〜T3 / T1 のみ）、閾値（1 / 4 / 10 便）、有向・無向、機材の区分、時刻の基準、期間、地域
- 空港の集合は条件ごとに変わります。
- 候補のリストは基準のネットワークで決めて固定します。ある条件に存在しない空港は影響 0 として扱い、`absent` に数えます。

順位の比較は2通りで計算します。

- **固定リスト**：全候補で比べ、不在の空港は 0 とします。
- **共通**（spearmanCommon）：両方の条件に存在する空港だけで比べます。

T1 のみは判定が厳しいだけで、より正確なネットワークではありません。2026年3月の地図上の便では、T1 の割合は北米 74%・欧州 71%・オセアニア 72% に対し、アジア 18%・南米 13%・アフリカ 36% です（アジアと南米は 6 割以上が T4）。北京首都（PEK）、ボゴタ（BOG）、ヨハネスブルグ（JNB）、カサブランカ（CMN）には T1 の便が1便もなく、T1 のみの条件ではネットワークから消えます。結果を見るときは「受信網の薄い地域の便を落とした条件」として読んでください。

## 4. 欠測の実験

観測された便を想定したモデルで取り除き、ネットワークを作り直すことを繰り返します。便を加えることはしません。

- 便ごとに残すか落とすかを決め、残った便で組の便数を数え直してから閾値を適用します。
- 空港の集合は基準のネットワークに固定します。すべての接続を失った空港も孤立ノードとして残るため、効率の分母は試行間で同じです。
- 1つの試行の中では、すべての候補が同じ欠けたネットワークで評価されます。
- 試行 0 は欠測なし（基準）です。統計は試行 1〜R だけで計算します。

### モデル

| モデル | 便が落ちる確率 |
| --- | --- |
| A 一様 | すべての便で p |
| B 地域別 | 出発地の大陸の確率 po と到着地の大陸の確率 pd を、下の規則で組み合わせる |
| C 低頻度路線 | 基準ネットワークで組の便数が閾値未満なら rateLow、それ以外は rateOther |

大陸は空港ごとに決めます（OurAirports の大陸。`research-web/quality.json` の `airportContinents` と、国の多数派の `continents`）。カナリア諸島は AF、スペイン本土は EU、ロシアは空港ごとに EU と AS に分かれます。Phase 9F より前は国の最初の空港の大陸を国全体に使っていたため、スペイン全体が AF、ロシア全体が EU になっていました。結果の `dataset.continentRule` が `airport-v1` でない結果は古い規則で計算されたもので、読み込むと警告します。

B の組み合わせ規則：

| 規則 | 確率 |
| --- | --- |
| max（既定） | max(po, pd) |
| either | 1 − (1 − po)(1 − pd)。どちらかの端で独立に取り逃す |
| both | po · pd。両端で取り逃したときだけ落ちる |
| origin / destination | po だけ / pd だけ |

C には単位が2つあります。

- **flight**：各便が独立に確率 rateLow で落ちます。
- **route**：低頻度の組ごとに1回だけ乱数を引き、その組の便がまとめて消えます。

「低頻度」の判定は、基準ネットワーク（基準の期間・ティア・区分、両方向の合計）で行い、定義ファイルに `thresholdPeriod` として記録します。

## 5. 乱数と再現性

- 試行 t の乱数は（シード, t, ストリーム）だけから作ります。Python は `numpy.random.SeedSequence([seed, t, stream])` と PCG64、ブラウザは同じ3つの値を混ぜたシードの mulberry32 です。どの順で、何並列で回しても同じ結果になります。
- Python は便を flightId の順に並べてから乱数を割り当てます。
- ブラウザは集計済みの行（路線 × 向き × ティア × 航空会社）で、行の便1本ずつに乱数を引きます。モデルとしては便単位と同じですが、乱数列は Python と異なります。このため、ブラウザとバッチの試行は分布として一致し、1回ごとの値は一致しません。
- 経路計算の起点のサンプルは `sourceSeed` から作り、両言語で同じ値になります（mulberry32 の部分 Fisher–Yates、テストで照合）。
- 実験の定義の内容からハッシュ（`definitionHash`）を作り、結果に記録します。名前と ID は含めません。ハッシュ関数は Python（SHA-256 の先頭 16 桁）とブラウザ（FNV 系の 2 本）で異なるため、同じ定義でも両者のハッシュは一致しません。同じ側で作った結果どうしの照合に使ってください。

## 6. 厳密計算と近似計算

- **厳密**：すべての空港を起点に幅優先探索をします。
- **近似**：k 空港を起点にします（ブラウザの既定は 1,024、バッチの例の定義は 256）。候補ごとに起点を変えると候補間の比較に起点の違いが混ざるため、同じ実行の中では全候補で同じ起点を使います。
  - 効率は起点 s ∈ S についての平均で推定し、組の数は (n − 1)/|S \ {v}| 倍して全体に換算します。
  - Spillover の「前」は、候補ごとに探索し直さず、最初の1回の探索の行和（起点ごと）と列和（行き先ごと）から v の行と列を引いて求めます。
- 順位をつける前に値を 1e-12 で丸め、足し算の順序による誤差で同順位が分かれないようにします。順位は同順位を最上位にそろえる方式です（"1224"）。

近似の誤差（起点のサンプリング誤差）は、条件や試行によるばらつきとは別のものです。両者を混同しないよう、結果には `exact` と起点の数を記録します。3月の基準ネットワークで厳密と近似（256 起点）を比べた結果は [phase9e-report.md](phase9e-report.md) の 9 節にあります。

## 7. 統計

空港ごと・指標（Systemic / Spillover）ごとに、試行（欠測）または条件（感度分析）にわたって次を計算します。

- 値：平均、中央値、標準偏差（ddof = 1）、p05・p25・p75・p95、最小・最大。分位点は numpy の既定（線形補間）です。
- 順位：同じ統計と、上位 k（定義の `topK`）に入った割合。

実行ごとには、基準の実行に対する Spearman、Kendall の τb、上位 k の重なり（基準の上位 k のうち、その実行でも上位 k に入る割合）、Jaccard を計算します。

これらは実行の分布を記述するもので、信頼区間ではありません。

- 欠測の実験のばらつきは、**想定した**欠測モデルのもとでのばらつきです。実際の観測の欠けがそのモデルに従う保証はありません。
- 感度分析の違いは、ネットワークの作り方の選択による違いで、観測誤差の推定ではありません。

### 安定性の区分（表示用）

順位の p05〜p95 の幅が 3 位以内、または基準順位の 4 分の 1 以内なら「安定」、それ以外を「条件に依存」としています。この線引きは見やすさのための便宜的なもので、統計的な検定ではありません。

## 8. 結果の形式

ブラウザとバッチは同じ JSON（`format: "1090web-experiment-result"`, `schemaVersion: 1`, `methodVersion: "9e.1"`）を書き出します。

- `definition`：実験の定義全体（シード、条件、モデル、候補の規則）
- `dataset`：データセットの ID とバージョン
- `computation`：厳密か近似か、起点の数、シード
- `runs`：実行ごとのネットワークの大きさ、不在・孤立の空港、比較の統計、完了したか
- `airports`：空港ごとの基準の値、実行ごとの値と順位、統計
- `complete`：取り消し・失敗した実行がある場合は false

研究モードは読み込み時に、形式、スキーマのバージョン、空港の行と実行の数の整合を確認します。データセットやバージョンが違う、未完了、近似、手法のバージョンが違う場合は警告を表示します。
