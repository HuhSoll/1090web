# Phase 9H 報告：イベント・インテリジェンスと過去の航空危機の分析

Phase 9G の EASA 安全勧告（CZIB）の研究を、ほかの種類の実際の出来事にも使えるように広げました。対象は安全保障上の出来事、空域制限、空域閉鎖、空港閉鎖、再開、安全勧告です。これらを 1 つのデータベースと 1 本のタイムラインにまとめ、同じ前後比較を行えるようにしています。初期の研究ケースは 2026-02-20〜2026-03-20 の中東です。

- 計算方法：[event-intelligence-methodology.md](event-intelligence-methodology.md)
- 使い方：[event-intelligence-guide.md](event-intelligence-guide.md)
- データの出典：[event-intelligence-sources.md](event-intelligence-sources.md)

この報告の数値は、観測された ADS-B の便を記述的に比べたものです。どの出来事の効果（因果効果）も示していません。同じ日に攻撃、勧告、各国の閉鎖、航空会社の判断が重なっており、それぞれを切り分けることはできません。

## A. 実装したイベント・インテリジェンス機能

| 機能 | 内容 | 実装 |
| --- | --- | --- |
| 出典の取得 | 出典の一覧（URL、発行元、種類：当局・保存版・国営通信・報道）を作り、文書をダウンロードする。取得の状態、HTTP ステータス、取得時刻、SHA-256 を記録する。取得できなかった出典は理由とともに残す | `pipeline/events/sources.json`、`fetch_sources.py`、`sources-documents.lock.json` |
| イベントの記録 | 出典を読んで手で記録した事例ファイル。各時刻にはそれを述べた出典を付ける。確認できなかった事柄は「未取得」の一覧に残す | `pipeline/events/curated/middle-east-2026.json` |
| 検証と公開 | 種類、状態、閉鎖の範囲を確認する。ほかに次の点を検査し、通らない記録は理由とともに除外する：出典を取得済みか、時刻の出典がそのイベントの出典か、日付だけの時刻に UTC が付いていないか、UTC と現地時刻が一致するか、検証状態が出典の種類に合っているか、再開が再開対象を示しているか、ID や文書の重複がないか | `pipeline/events/build_registry.py` → `public/data/events/events.json` |
| 共通のモデル | 7 種類のイベント、5 段階の検証状態。発生、発表、有効の開始、有効の終了、初めて確認した時刻は分けて持つ。時刻は精度（分・時・日付・月・不明）を保ち、出典ごとの値を統合しない。対象（国、FIR、空港、高度、運航者、機材）も分けて持つ | `src/events/registry.ts` |
| CZIB との互換 | Phase 9G の CZIB の各版は、ブラウザ側で `CZIB:<勧告>/<版>` の安全勧告に変換する。9G の履歴ファイル、URL、保存 JSON の形式は変えていない | `czibEvent`、`study.ts` |

| 絞り込み | 期間、国・FIR・空港、種類、検証状態、文字列 | `filterEvents` |
| イベントの詳細 | 時刻を出典ごとに、精度と根拠とともに表示する。確認できること・できないことを分け、出典と SHA-256 を示す。前後 3 日のイベントは「出典で述べられた関係」と「時間的に近いだけ」に分ける | `EventDetail` |
| 前後比較 | 9G の比較（前後、事前トレンド、プラセボ、DiD の条件、仮想停止との比較）を、国の指定があるすべてのイベントで実行できる | `subjectOf`、`runStudy` |
| 比較期間のイベント | 前、イベント日、後の各期間に有効だった、または起きたイベントを対象地域に限って一覧にする。日付だけの出来事が時差で期間の端に数時間だけ重なる場合は、その旨を示す | `WindowEvents` |
| 結果のキャッシュ | 同じイベント・条件の結果はタブを切り替えても再計算しない | `studyCache` |
| 保存 | イベント一覧（CSV）。研究結果の JSON は、CZIB では 9G と同じ形式、ほかのイベントでは時刻・出典・イベント日の根拠を記録する | `eventsCsv`、`studyJson` |

- 3 か国とも、観測便はイベント日の翌日からほぼ途絶えました（カタールは DOH 616 → 16 便/日、DIA 58 → 0.1 便/日）。UAE は 2 割ほどが残りました。UAE 国内の路線（A）は 19 → 1 便/日です。
- 9G の R0 は 11 か国をまとめた地域です。対象地域が違えば周辺国と比較対象群も変わるため、国ごとの行と R0 の行は直接比べられません。
- 3 か国とも前の期間に減少傾向があり、UAE とカタールでは |t| ≥ 2 でした。ただし比較対象群との比では |t| < 2 のため、DiD の条件は形式上満たしています。周辺国も前の期間に −12% 前後の傾き（|t| > 2）があり、地域全体が 2 月下旬から減っていたことがわかります。
- 便名から空港を推定した便（T4）の割合は、後の期間で UAE 82%、カタール 100%、クウェート 100% でした（クウェートは前の期間も 100%）。後の期間に残った便が実際にその国を発着したかどうかは確かめられません。
- 仮想停止との比較：「経路がなくなるほかの空港の組」は、UAE では観測（対象地域の路線だけ変更）27,128、仮想停止 43,899 です。カタールはどちらも 0 で、ドーハ経由の組は別の経路で残ります。クウェートは観測 3,312、仮想停止 6,771 です。「全路線」の値（約 130 万）は同じ期間に世界中で起きた変化を含むため、イベントの比較には使えません。
- 比較期間のイベント一覧では、UAE の日付だけの 2 件（現地 2/28 は UTC 2/27 20:00〜2/28 20:00）が前の期間の最後の 4 時間に重なるため、「時差で数時間だけ重なる」と表示されます。

## D. EASA 以外の情報から新たに分かったこと

- **時刻の順序**：EASA CZIB 2026-03 R0 は発行日（2026-02-28）しかわからず、最も早い保存版は 13:11 UTC です。一方、カタールの停止の報道は 09:21 UTC、ハマド空港の停止は 10:13 UTC、UAE の部分閉鎖の報道は 09:42 UTC でした。各国の措置の報道は、確認できる EASA の最初の保存版より 3〜4 時間早いことになります。ただし EASA の発表時刻は不明なので、EASA より先だったとは言えません。
- **範囲の違い**：UAE は「一時的・部分的」な閉鎖で、GCAA の安全決定が確実に止めたのは無人機と軽スポーツ機だけです。それでも観測便は 8 割減りました。閉鎖の範囲と便の減り方は一致しません。
- **FAA は危機中に新しい措置を出していない**：2026-02-12〜04-07 の FAA の制限一覧の保存版 4 つには、同じ 3 文書（SFAR 117、SFAR 77、KICZ A0016/20）しか載っていません。どれも危機の前から有効で、対象は米国の運航者だけです。全体の閉鎖として扱ってはいけないことが記録で確かめられました。
- **期間**：クウェートの閉鎖は報道では 2026-04-23 の夜に再開しており、およそ 8 週間続きました。カタールについては、3 月 7 日の時点でも閉鎖が続き、特別便だけが運航していたと報じられています。
- **9G との関係**：9G で R0 の前に見られた減少（事前トレンド t = −4.5）の一部は、同じ日の各国の措置と重なっています。勧告の効果と国の措置の効果は、この観測では分けられません。

## E. データが足りずに分からなかったこと

- 各国の当局による閉鎖の文書（QCAA、クウェート DGCA、バーレーン、イスラエル）と NOTAM。報道とカタール国営通信しか得られず、正確な開始・終了時刻と例外（特別便など）は確認できません。
- EUROCONTROL の NOTAM（EAD）と交通統計のページは、パイプラインから取得できませんでした（HTTP 403）。
- イスラエル、バーレーン、イラン、イラク、ヨルダン、サウジアラビア、オマーンの国内措置。この期間には探していません。
- 攻撃の正確な時刻。EASA の文面は日付しか示しておらず、報道の時刻は採っていません。
- 1090web の観測は地上局の範囲に左右されます。湾岸の後の期間の便はほとんどが便名からの推定（T4）で、実際の発着とは限りません。航空機が空域を通過したかどうかは推定していません（今回の範囲外）。

## F. UI・UX の改善結果

- 研究モードのタブ名を「過去のイベント」から「イベント調査」に変えました。CZIB の版の選び方、イベントのカード、9G の結果の表示はそのまま残しています。
- 統合タイムラインでは、日付だけの出来事を 1 日全体の斜線で示し、00:00 の点には置きません。報道だけの出来事は破線です。重なりは上部の帯で示します。D（観測便数）は比較を実行すると表示されます。
- 種類の選択肢は、色見本と名前が別の行に分かれていたため、1 つのまとまりにしました。
- 前後 3 日のイベントの一覧では、以前から有効なもの（SFAR 117 など）に「それ以前から有効」と付けて後ろに並べ、その時期に始まったものと区別しました。
- 対象地域内の便が 1 日 1 便未満のとき、比率（例：0 → 0 便で −50%）ではなく「—」を表示します。
- 比較の説明文は「勧告」を「イベント」に変えました。閉鎖を調べるときにも文意が合います。
- シミュレーションのタイムラインの実際のイベントは、A・B・C の 3 行に分けて表示します。押すと研究モードのイベント調査を開きます。名前は日本語で表示します。

## G. テスト・性能・残っている課題

### テスト

- TypeScript：`tests/events/registry.test.ts`（22 件）。内容は次のとおりです。
  - 公開データの検証と、報道だけのイベントの状態。
  - 日付は 00:00 UTC にならず 1 日全体になること（Asia/Dubai で 2/27 20:00Z から）。夏時間のある地域や不明な地域は「不確か」になること。
  - 出典ごとの時刻の保持と矛盾の検出。
  - FAA の運航者の範囲と高度、再開の関係。
  - CZIB の互換（ID、日付、版の終了）、9G と同じイベント日。
  - 絞り込み、期間、重なり、行の割り当て、レイヤー。
  - シミュレーション・離島・実験・時系列のコードが記録を読まないこと。
  - `ei.*` の日英の対応。
- Python：`pipeline/tests/test_registry.py`（16 件）。日付の UTC、現地時刻との一致、時刻の出典、状態と出典の種類、未取得の出典、重複と不明な値、再開の関係、運航者・高度の保持、記録の版、公開データ。
- 全体：vitest 272 件、pytest 193 件、型検査、lint、GitHub Pages 向けのビルド（`BASE_PATH=/1090web/`）がすべて通りました。

### 処理性能

キャッシュのないイベントの比較は約 11 秒でした（クウェート、14 日、データ読み込み済み）。同じ条件の 2 回目はキャッシュから 0.1 秒以下で表示されます。

### 残っている課題

- 各国当局の文書と NOTAM の取得。EAD は登録が必要で、再配布もできません。
- 中東の残りの国と、ほかの地域の事例。
- 対象が FIR だけのイベント（KICZ A0016/20 など）は、国の指定がないため比較できません。FIR から空港を選ぶ方法は未実装です。
- タイムゾーンは固定の時差だけを扱います。夏時間のある地域の日付は UTC の範囲を「不確か」とします。
