# 研究成果（Phase 9I）

Phase 9A〜9H の研究上の主張を、Phase 9I の監査のあとで整理した一覧です。研究モードの「研究成果」タブで、根拠・条件・限界とともに確認できます。成果を選ぶと元の分析（イベント調査、離島の依存性、実験、地図の時間窓）を開けます。

データは `public/data/findings/findings.json` にあり、研究成果タブを開いたときだけ読み込みます。

## 検証状態

| 状態 | 意味 |
| --- | --- |
| 検証済み（Validated） | 記したデータ・条件・範囲について、独立した計算や十分な再確認で確かめた結果。現実の世界で絶対に正しいという意味ではありません |
| 条件付きで支持（Conditionally Supported） | 記した観測条件・仮定・モデルのもとで支持される結果 |
| 予備的（Preliminary） | 興味深いが、独立した検証や対象の範囲が足りない結果 |
| 要再検証（Needs Review） | 数値や解釈に問題が見つかり、再検証が必要な結果 |
| 支持されない（Not Supported） | 再検証の結果、記したとおりには支持できなかった主張。訂正の経緯をたどれるよう記録を残します |

各成果の根拠・確かめ方・条件・再現の方法は、研究成果タブと `findings.json` にあります。

## 形式

各成果は次の項目を持ちます（日本語・英語）。

`findingId`, `title`, `researchQuestion`, `statement`, `dataset`（ID と版）, `period`, `method`, `conditions`, `evidence`, `validationStatus`, `validation`（確かめ方）, `limitations`, `relatedExperiments`, `sourceReferences`, `calculationVersion`, `lastVerifiedAt`, `link`（元の分析）, `reproduce`（再現の方法）

必要な項目が欠けた成果は表示しません（推測で補いません）。「検証済み」「支持されない」以外の成果には、限界の記載が必要です。テスト（`tests/research/findings.test.ts`）で次を確かめています。

- 形式
- 関連する実験の設定ファイルと出典のファイルが存在すること
- イベント・空港のリンクが存在すること

## 成果を加える・変えるとき

1. 主張を、データ・期間・条件・範囲を限定して書きます。
2. 可能なら別の実装で計算し直し、`pipeline/research_validation/` にスクリプトを置きます。
3. 確かめた範囲に合う状態を選びます。独立の検証がない成果を「検証済み」にしないでください。
4. 主張が誤りと分かったら、成果を消さず「支持されない」に変え、元の報告に訂正を追記します。
5. `lastVerifiedAt` と `calculationVersion` を更新します。
