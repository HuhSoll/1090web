## 2. 時刻の定義

| 名前 | 定義 |
| --- | --- |
| `trackStartTime` | ADS-B 航跡の最初の点（UTC）。離陸時刻とは限らない |
| `trackEndTime` | 航跡の最後の点（UTC）。着陸時刻とは限らない |
| `referenceTime` | `trackStartTime`、なければ `trackEndTime`（現行の月次データと同じ定義） |
| `timeBasis` | `TRACK_START`／`TRACK_END_FALLBACK` |

- 時間窓は半開区間 [start, end)。`start <= referenceTime < end` の便を数えます。
- 「その時間に飛んでいた可能性のある便」は別の選び方として区別し、今回は実装していません（研究用データに航跡の開始・終了時刻があるので、後で追加できます）。
- 出発側の時刻がない便に、出発時刻を補って作ることはしていません。
- 元データの時刻は UTC（タイムゾーン表記なし）です。

## 4. 日次・時間単位の集計方法

- **月次**：既存の月別ファイル（変更なし）。
- **日次**：その UTC 日付のファイル1つ（約 0.8 MB、gzip 約 0.24 MB）。
- **1時間・6時間・任意の時間窓**：窓に重なる日のファイルを読み、分単位の基準時刻で [start, end) を二分探索で選びます。境界が分ちょうどの窓は、秒まで使った場合と同じ便を選びます。日をまたぐ窓は2日分を読みます。
- 選んだ便は、Research Mode の月データと同じ形（`ResearchMonth`）に変換できるので、根拠区分・分類・航空会社・地域・閾値の絞り込みと、すべてのネットワーク指標がそのまま使えます。
- 方向別（路線 × 方向）と無向（路線）のどちらでも、各便は1回だけ数えます。路線数（辺の数）と便数は別に数えます。

## 7. 公開用データの形式と容量

形式の比較（2026年3月の1日あたり、実測）：

| 形式 | 生 | gzip | 1時間単位の再構成 |
| --- | --- | --- | --- |
| A 日別の路線集計 | 0.95 MB | 0.17 MB | できない |
| A2 1時間ごとの路線集計 | 1.7 MB | 0.34 MB | 1時間単位のみ |
| B 時刻順のイベント（秒・継続時間つき、最初の案） | 1.36 MB | 0.48 MB | できる |
| **B 路線ごとにまとめたイベント（分、採用）** | **0.79 MB** | **0.22 MB** | **できる** |

採用した形式は日別の路線集計より生のサイズが小さく、日次・1時間・任意の窓をすべて再構成できるため、日別集計とのハイブリッド（C）は採用しませんでした。継続時間（航跡の長さ）と秒単位の時刻は研究用データにだけ残しています。

## 10. GitHub Pages 配信上の制約

- 公開用データは日別に分割し、ブラウザは必要な日だけを読み込みます（全期間を一括で読み込むことはありません）。1つの窓で読み込む日数は最大 10 日（メモリ上の上限）。それより長い期間は月次データを使います。
- 1ファイルは最大 0.96 MB（GitHub の上限 100 MB を大きく下回る）。サイトの合計は既存のデータ（約 130 MB）と合わせて約 350 MB で、GitHub Pages の上限 1 GB に収まります。
- リポジトリは約 65 MB（圧縮後）増えます。2026年10月以降を追加すると1か月あたり約 25 MB（gzip 約 7 MB）増える見込みです。年単位で増える場合は、古い年の日別ファイルを Releases に移すなどの方針が必要になります。
- **公開データはまだ GitHub に push していません。** push すると、日別ファイルがサイトで配信されるようになります（画面からはまだ使いません）。

## 12. 将来のシミュレーションへの拡張方法

- 時間軸（どの便がいつ観測されたか）とネットワーク（便からグラフを作り、指標を計算）を別のモジュールにしています。シミュレーションは、観測データを変えずに「仮想イベント」（空港の停止・再開、路線の停止、容量削減）を時間窓ごとに辺へ適用する層として追加します。
- 観測の時刻（`referenceTime`）とシナリオの時刻は別の型で持ち、混ぜません。
- 同じ窓について「観測ネットワーク」と「シナリオ適用後のネットワーク」を並べて、Research Mode の比較機能（順位相関・上位の一致率）で比べられます。
- 「その時間に飛んでいた可能性のある便」で窓を作るモードは、研究用データの航跡の開始・終了時刻を使って追加できます（公開用データに継続時間を加えるかは、容量と合わせて判断）。

## 残っている制約

- 公開用の時刻は分単位です（窓の境界が分ちょうどなら正確）。
- 航跡の開始時刻は離陸時刻ではありません。出発側の時刻がない便（9.8%、アジア・アフリカ・南米で多い）は終了時刻で数えています。
- 1つの窓で読み込めるのは 10 日分までです。
- 2026年5月5〜7日の収集停止の期間は、日別・時間別のデータでもほぼ空です（補正はしていません）。
- 画面での利用（Phase 9B）は未実装です。
- 研究用 Parquet（約 611 MB）の Releases での配布は、承認後に実行します。
